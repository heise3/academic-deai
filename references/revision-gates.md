# 长稿的长度与结构核查

本参考解释可选工具的信号。用户明确的长度、章节和编辑深度约束优先；工具阈值不替代语义、证据与读者功能判断。

## 用户约束

从请求记录最低字数/词数、允许压缩幅度、需保留的章节、标题层级、稿件用途和输出格式。没有给出的数值不应变成新审批条件。用户明确要求的最低长度是硬约束，不能用“更精炼”覆盖。

去模板化可以删去重复与空话，但要保留独有数据、机制、比较、条件和方法信息。大幅压缩超出既定范围时，先完成范围内的编辑，再说明需要用户决定的实质取舍。

## 解释保留率

脚本可配置总体和分节保留率。旧版示例的 65% / 50% 是复核起点，不是所有稿件的默认合格线，也不自动限制用户授权的摘要或压缩任务。

长度下降只触发内容复核：列出被删除的独有命题与必要信息，核对它们是否已在合并后的段落中保留。长并不等于完整；保留率高也可能丢掉一个否定或条件。不要为满足比例填充、复制段落或恢复套话。

## 结构重复

检查长稿时注意：

- 多节使用相同段数与相似句数；
- 每节反复“提出机制—指出不足—要求未来研究”；
- 全文持续纠正未提出的错误解释；
- 大多数章节都以裁判式结论或相同展望收尾。

先看章节的真实任务。定义、方法、结果、争议和综合可以有不同组织方式；同一报告规范也可以要求重复结构。严谨不需要每节都宣告“作者判断”，也不需要每节都加入一段否定。

必要的组间对比、阴性结果、证据限制、标准方法和摘要回扣应保留。参见 [模式参考](source-patterns.md)。

## 来源缺口与编辑残留

保留真实署名、引文及支持位置。不要编造补充来源，也不要把编辑过程说明放入成稿。来源缺口较多或用户要求追踪时，可使用 [claim-source ledger 模板](../assets/claim-source-ledger-template.csv)；否则只需紧凑说明实质未决项。

如果用户要求带注释草稿，保留其需要的标记；如果要求 clean copy，编辑说明放在正文外。不要仅为了洁净度删除研究本身的真实限制。

## 工具用法

```sh
python3 scripts/revision_gate.py original.md revised.md --help
python3 scripts/rhetorical_texture.py revised.md --language auto
```

需要显式长度门槛时，使用任务确定的 `--min-output-units`、`--min-overall-retention` 或 `--min-section-retention`。中文有效单位以汉字计，英文以词计，不等于所有期刊的字数规则。

`rhetorical_texture.py --anti-template-strict --strict` 可用于特意进行的模板结构压测。严格失败要求多个信号组合；普通修改无需自动进入严格模式。

`revision_gate.py` 还可报告标题缺失、来源占位符、编辑残留和摘要/结论的可观察相似性。这些指标不判定作者身份。

## 交付状态

仅在用户要求审计报告时给特征状态。可写“已解决”“部分保留及原因”或“需要语义复核”，并附可核对的位置。词语消失不能单独证明问题解决：核对它原本携带的信息是否仍在。

脚本通过只确认该工具覆盖的可观察项；最终保真复核仍应对照实际命题。适用检查通过且无具体剩余问题时，不重复扩展核查。
